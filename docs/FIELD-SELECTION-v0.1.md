# ENVOY — FIELD SELECTION v0.1

## 1. Purpose

This document defines the first reconnaissance filter for selecting a field in which Envoy can be deployed.

The filter is provisional.

It must be tested on real candidate fields before being expanded or treated as a validated method.

## 2. Candidate fields

Initial candidates:

1. UDRP
2. Specific types of domain disputes
3. New TLD domain disputes
4. Kleros / crypto arbitration

Platform appeals remain a reserve candidate.

## 3. Core filter

PUBLIC TRACE
CORPUS BOUNDARY
SOURCE ACCESS
EXISTING SYNTHESIS
UNRESOLVED STRUCTURAL QUESTION
ABILITY TO TEST
PRACTICAL VALUE

The filter is not assumed to be strictly linear.

A failure at an early gate may terminate consideration of a candidate.

A large corpus may be technically accessible but practically unsuitable because of time or processing cost.

## 4. Ability to test

ABILITY TO TEST has two separate dimensions.

### Technical accessibility

Can Envoy actually obtain and process the required material?

Questions:

- Is there a public corpus?
- Can the operator access it through available channels?
- Can the corpus be bounded to a workable subset?

### Methodological accessibility

Can the proposed research question be tested without requiring expertise that the operator does not possess?

Questions:

- Does verification require specialist expertise?
- Can the relevant claims be checked against accessible sources?
- Does lack of expertise create a hidden methodological confound?

Technical accessibility does not imply methodological accessibility.

## 5. Research and resource contours

PRACTICAL VALUE belongs to the resource contour.

It must not be silently mixed with research suitability.

Therefore candidate assessment should distinguish:

RESEARCH FIT
Can this field support a meaningful and testable investigation?

RESOURCE FIT
Can this field plausibly contain a practical niche with resource potential?

A candidate may have high Research Fit and low Resource Fit, or vice versa.

These outcomes must remain visible.

## 6. Assessment format

For each candidate:

- GATE: PASS / FAIL
- SCORE: 0–2 where scoring is appropriate
- UNKNOWN: insufficient information

Unknown is not automatically treated as failure and is not converted into a positive score.

## 7. Initial assessment dimensions

### PUBLIC TRACE
Is there sufficient public material to establish a reliable field trace?

### CORPUS BOUNDARY
Can the field be restricted to a manageable corpus?

### SOURCE ACCESS
Can the required primary material actually be obtained?

### EXISTING SYNTHESIS
How much of the relevant structure is already covered by authoritative summaries, reviews, or established frameworks?

### UNRESOLVED STRUCTURAL QUESTION
Is there a concrete question that remains open after accounting for known summaries and explanations?

### ABILITY TO TEST
Can the question be tested technically and methodologically?

### PRACTICAL VALUE
Is there a plausible resource-side opportunity worth investigating?

## 8. Important methodological rule

The filter itself is an experimental object.

Do not keep adding criteria before applying it.

First apply the current filter to several candidates.

Then record:

- where candidates differ;
- where the filter produces ambiguity;
- where information is missing;
- where the scoring fails to discriminate;
- where the filter itself creates a confound.

Only then revise the method.

## 9. First field-selection experiment

Compare the four initial candidates using the same assessment structure.

The purpose is not to select a winner immediately.

The purpose is to test whether the filter can distinguish fields in a useful and reproducible way.

## 10. Current status

STATUS: PROVISIONAL

The filter has not yet been validated.

The candidate list is exploratory.

No candidate is currently designated as the Envoy field.
