# ENVOY — ROADMAP v0.1

## 1. Purpose

This roadmap defines the initial sequence for launching Envoy.

It is a working roadmap, not a fixed long-term plan.

The roadmap should change only when field evidence, methodological problems, or explicit project decisions justify a revision.

## 3. Phase 0 — Documentation baseline

STATUS: IN PROGRESS

Establish the minimum operational documentation:

- project identity;

- field-selection filter;
- role separation;
- External configuration;
- initial roadmap.

Exit condition:

The documents are internally consistent and their provisional status is explicit.

## 4. Phase 1 — Clean External setup

Create exactly three clean External sessions:

- Kimi
- Grok
- Sakana

Each session must begin without prior Envoy conversation history.

Record:

- model identity;
- session identity where available;
- initial input;
- timestamp where available.

Exit condition:

All three External sessions are ready and provenance can be preserved.

## 5. Phase 2 — Independent field reconnaissance

Give all three External nodes the same initial reconnaissance task.

Candidates:

1. UDRP
2. Specific types of domain disputes
3. New TLD domain disputes
4. Kleros / crypto arbitration

Platform appeals remain a reserve candidate.

Each External assesses the candidates using the current field-selection framework.

No External sees another External's response during this phase.

Exit condition:

Three independent responses are preserved.

## 6. Phase 3 — Lead comparison

The Lead compares the three independent outputs.

The comparison must record:

- agreements;
- disagreements;
- unknowns;
- unsupported assumptions;
- missing evidence;
- differences in candidate ranking;
- cases where the filter fails to discriminate.

The Lead must not force consensus.

Exit condition:

A comparison artifact exists that distinguishes External observations from Lead interpretation.

## 7. Phase 4 — Filter assessment

Evaluate the field-selection method itself.

Ask:

- Did the gates distinguish candidates?
- Did the scores add useful discrimination?
- Did UNKNOWN remain usable?
- Did Research Fit remain separate from Resource Fit?
- Did Ability to Test expose hidden methodological constraints?
- Did the filter create ambiguity or confounds?

Do not add criteria merely because the first result is inconvenient.

Exit condition:

The method is either retained for the next cycle or explicitly revised.

## 8. Phase 5 — Controlled interaction

Only if useful after the independent phase, introduce selected External outputs into controlled interaction.

Record:

- participating nodes;
- input order;
- supplied material;
- interaction stage;
- resulting changes.

Independent and interaction-derived observations must remain distinguishable.

Exit condition:

Any interaction result can be traced back to its independent starting state.

## 9. Phase 6 — Field decision

The Architect reviews the reconnaissance and Lead synthesis.

Possible outcomes:

### A. Select a field

A candidate has sufficient Research Fit and/or Resource Fit to justify deployment.

### B. Continue reconnaissance

The current evidence is insufficient to select a field.

### C. Revise the filter

The method itself failed to discriminate candidates adequately.

### D. Reject the candidate set

The initial fields do not provide a suitable starting point.

No outcome is required in advance.

## 10. Phase 7 — First field cycle

If a field is selected:

FIELD
↓

↓

↓

↓

↓

↓

The first field cycle should remain small enough to preserve traceability.

The objective is not immediate scale.

The objective is to establish whether Envoy can produce cumulative, verifiable field knowledge and identify practical opportunities.

## 11. Phase 8 — Method revision

After the first field cycle, review:

- what worked;
- what failed;
- what remained unknown;
- which assumptions were wrong;
- which records proved useful;
- which procedures created unnecessary overhead;
- whether Research and Resource contours remained distinct.

Any substantive methodological change receives a new version.

## 12. Decision gates

Envoy should not advance merely because time has passed.

Suggested gates:

DOCUMENTATION READY
↓
EXTERNALS READY
↓
INDEPENDENT RESPONSES PRESERVED
↓
FILTER ASSESSED
↓
FIELD DECISION
↓
FIELD CYCLE
↓
METHOD REVIEW

A failed gate may require revision rather than progression.

## 13. Stop conditions

Envoy may pause or stop when:

- required evidence cannot be obtained;
- the field cannot be investigated responsibly;
- methodological validity cannot be maintained;
- the practical value is insufficient for the resource contour;
- the research question collapses under verification;
- the project no longer justifies its operational cost.

Stopping is a valid result.

## 14. Revision rule

This roadmap is provisional.

Do not expand it into a detailed long-term architecture before the first reconnaissance cycle.

The first cycle is itself a test of the roadmap.

Revisions should record:

- what changed;
- why it changed;
- what evidence caused the change;
- which version replaced the previous one.
